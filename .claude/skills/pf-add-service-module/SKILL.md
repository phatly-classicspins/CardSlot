# Add a service module (a third-party SDK behind an existing framework port)

Full recipe: **`docs/framework/recipes/add-service-module.md`**. The rule behind all of it: **the
framework must not know a module exists, and a module must not know a game exists.**

## 0. The gate before you write anything

| What you have | Where it goes |
|---|---|
| An **external-SDK implementation of a port that already exists** | A module package — this skill. |
| Logic with **no external dependency** | Register it in the SKU installer. No module. |
| A **new port / event type / `BootCap` / RenderLayer / migrator / broker**, or a fifth role | **Spine change** — route it first. |

A module **defines no seam**: it implements an existing port, occupies the installer slot, and may
replace one boot node. It lives in **its own package** — never inside the framework package, never
under `Assets/<Sku>/`.

## 1. Layout — four roles, one gated

```
Packages/com.classicspins.pf-<domain>/
├── package.json        depends on the framework ONLY — never the SDK
├── pf-module.json      the self-description, single source of truth
├── Runtime/Core/       <Domain>.Core     engine-free, ungated: port impl, I<Sdk>Bridge, boot node, preflight rules
├── Runtime/Sdk/        <Domain>.Sdk      GATED by PF_<SDK>: <Sdk>Bridge + PfModuleMarker_PF_<SDK>
├── Runtime/            <Domain>          UNGATED: <Sdk>Installer (ScriptableObject : IInstaller) + Null<Sdk>Bridge
├── Editor/             <Domain>.Editor   editor-only, ungated, #if inside: IModulePreflight
└── Tests~/<Module>HeadlessTests/         globs Runtime/Core/** only — CI step 5c
```

- The **`Sdk` role is the only define-gated assembly** (`defineConstraints: ["PF_<SDK>"]`) and the only
  runtime assembly naming an SDK type. `versionDefines` on the SDK's UPM package arms the define —
  never a Player Settings symbol. The runtime and Editor roles carry the same `versionDefines` and
  **no** `defineConstraints`.
- The ungated runtime role's `#if PF_<SDK>` reference into `Sdk` is legal only because Unity drops a
  reference to an unsatisfied-constraint assembly — cite `UnityCsReference`
  `CustomScriptAssembly.cs:568` → `EditorBuildRules.cs:244, 451-465`.
- References: runtime roles → `CS.PF.{Application, Domain}`, VContainer, UniTask, own assemblies, SDK
  runtime asm. Editor adds `CS.PF.Editor` + the SDK's editor asm. **Never** Presentation, Views,
  Infrastructure, Composition or `Game.*`. No SKU assembly references the SDK.
- The **marker** `internal static class PfModuleMarker_<DEFINE> { }` in the `Sdk` role is how the
  Wizard and Doctor confirm the gated assembly compiled.
- The SDK must come through **UPM** — a `.unitypackage` lands in `Assembly-CSharp`, unreferenceable.

## 2. `pf-module.json`

Required: `schema` (`pf-module/1`), `id` (== `package.json` `name`), `displayName`, `frameworkRange`
(node-semver), `port` {`interface`, `mode` `replacement`|`additive`, `replacesBootNode` — key required,
`null` if none}, `requires` {`scopedRegistries[]`, `dependencies{}` — **exact pins**}, `define`,
`installer` {`type`, `menu`, `assetPath` with `{sku}`}. Optional: `summary`, `source`, `manualSteps`
(human zone, shown verbatim, never performed), `docs`.

## 3. Absence refuses — never falls back

The installer always registers **your** port implementation; only the bridge depends on the define —
`#if PF_<SDK>` → `<Sdk>Bridge`, else `Null<Sdk>Bridge`, which **fails every call as a result and logs
the module id**. Never leave the framework fake resolved: `FakeAdsService` auto-rewards. A gated
installer is the same bug (the slotted asset becomes a missing script).

## 4. The shipped fake is the specification

- **`IAdsService`** — `AdVisibilityChanged` at show-start **and** in a `finally` at show-end; auto-log
  every outcome via `AdAnalyticsMapping` → `IAnalytics`.
- **`IAnalyticsProvider`** — never throw; `FanOutAnalytics` re-queues on a throw.
- `I<Sdk>Bridge` speaks **primitives only**; the state machine lives in `Core` under `dotnet test`.

## 5. Boot node — replace, never add

```csharp
builder.Register<MaxAdsInitNode>(r => new MaxAdsInitNode(…), Lifetime.Singleton);
builder.Register<BootNodeOverride>(
    r => BootNodeOverride.Replace("AdsInit", r.Resolve<MaxAdsInitNode>()), Lifetime.Transient);
```

`Id` and `Provides` identical, `Required => false`, node registered as itself (never `IBootNode`),
override `Transient`, one module per target. `Replace` does not enforce `Id`/`Provides` yet — your
module's headless tests must.

## 6. Ads consent is the SDK's (AD-MOD-9)

The replacement node does **not** inject `IConsentService`; the bridge has **no consent setter**;
nothing is written back. `Requires` stays on `ConsentResolved`. **No timeout** over the interactive
flow; `AdVisibilityChanged(true)` before it, `(false)` in a `finally`. SDK init + consent run **once per
process**, memoized (never UserData); can-show keys on the bridge's own state, never `IBootStatus`.

## 7. `IModulePreflight`, never a build hook

A module never implements `IPreprocessBuildWithReport` — the `buildhook` grep fails it. Implement
`IModulePreflight` (`ModuleId`, `Check(BuildTarget)` → `ModulePreflightProblem`s) in the `Editor`
role; keep the decisions in `Core`. The framework's one `ModulePreflightBuildHook` aggregates every
module into one `BuildFailedException`. Mandatory for an SDK-bearing module — it is the only
enforcement that reaches a consumer's build. Third-party resolvers by reflection only.

## 8. No defaulted constructor parameters

VContainer resolves every parameter; `ILog log = null` is a hard dependency in disguise.

## 9. Install in a SKU — `Framework/Setup Wizard ▸ Modules`

Git URL → adds only the module package → reload → row `Partial` → **Install** writes registries and
pins to `Packages/manifest.json` only → **checklist** (`manualSteps`, installer menu, `assetPath`). The
installer-asset drop into the Master Scene slot is human zone. **Doctor check 16** shows the same
state and missing facts by name, and **reports, never blocks**. Distribution: git tag
`<slug>/v<version>`.

## 10. Gate

```sh
cd HeadlessTests && dotnet test              # framework-pure ship gate
sh Tools/CI/module-tests.sh                  # every module's headless project — CI step 5c
sh Tools/CI/greps.sh source                  # incl. the buildhook grep
Tools/Build/pf-build.sh modules --check      # pf-module.json vs code — CI step 3 (0 ok · 1 drift · 2 error)
```

EditMode via `Tools/pf/pf-tests` only when an `Editor` role changed. One **boot smoke** for the wiring.
The PlayMode suite is CI's; a real ad and the SDK consent flow are device-only — report them unverified.

## If it breaks

| Symptom | Cause |
|---|---|
| The fake still runs | Installer asset not slotted, or the installer assembly was gated. |
| Every call fails, logging the module id | `Null<Sdk>Bridge` — define not armed; Doctor check 16 names the fact. |
| `modules --check` names `define` / `installer.type` / `port.interface` / `id` | `pf-module.json` no longer matches the gated asmdef + marker / the installer class / the API index / `package.json`. |
| Build fails listing `[<module id>]` lines | Your preflight found a half-wired install. |
| Input locked / audio ducked after an ad or the consent prompt | Closing `AdVisibilityChanged(false)` not in a `finally`. |
| Deep link or consent rerun does nothing | A replaced node changed `Id` or `Provides`. |
