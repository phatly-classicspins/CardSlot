# UX asset handoff

Procedure detail: `docs/framework/recipes/ux-asset-handoff.md` (Part D for 3D). Mechanical steps:
`Tools/pf/ux-handoff.py` (`--help`). Extraction runs through `Tools/pf/asset-gen.py` (`pf-asset-gen`);
missing 3D models come from `pf-model-gen`.

**Goal:** when epics and build start, every surface has exactly one approved mockup to be judged
against, and every component names the sprites it uses and the size to import them at. In a 3D
game, every model also names its file, its import scale, its host and its clips, and every clip says
what plays it. All of it is linked from the spines, because downstream skills read only the spines
and what they point to.

**Who reads the output**

- `bmad-create-epics-and-stories` reads DESIGN.md + EXPERIENCE.md. Finish stories are judged
  against "the approved mockup", which is a PNG, because a vision referee cannot read HTML.
- `bmad-build` transcribes a story's Visual Contract from the design sources the intent names, then
  audits a capture.
- `pf-asset-gen` tells implementers that design-package art is used as-is. Look there first, and
  never regenerate approved art.

## Inputs and hard rules

- **Workspace** `<ws>`: a bmad-ux run folder, `{planning_artifacts}/ux-designs/ux-*`, holding
  DESIGN.md, EXPERIENCE.md, `.memlog.md` and `mockups/*.png`. Take the one the user names, else the
  newest whose DESIGN.md has `status: final`. Resolve `communication_language` (speak it) and
  `document_output_language` (write docs in it) from `_bmad/bmm/config.yaml`.
- **SKU**: the folder under `Assets/` that holds `*FrameworkSettings.asset`. Import destinations
  live under `Assets/<Sku>/` so `SpriteImportDefaults` applies PPU 1.
- **Mockups must be approved.** Look for the user's approval in `.memlog.md` or SURFACES.md. If
  there is none, stop and route to `bmad-ux`, because extracting from unapproved art wastes the
  quota.
- **Never modify, re-render or regenerate `mockups/*.png`.** They are the approved reference.
- **Never redraw approved art in code or vector form.** Missing art is a **Gap** for `pf-asset-gen`.
- **Nothing under `Assets/`.** Importing and resizing sprites is the first build story's job; this
  skill only writes the plan for it.
- **No composed-screen HTML as a reference.** A browsable kit is optional and shows component states
  only. Composed screens drift from the mockups and then get read as layout guidance.
- **3D is in scope when the world is drawn with models:** `models/*/model.gen.json` exists
  (`pf-model-gen`), the package has a `MODELS.md`, or any FBX/glTF sits in the package. A 2D game
  says so in one line and skips phase 5 and the `models:` block of phase 6.
- **Never re-author, re-export or retime an approved model or clip.** A wrong clip length is a
  finding for whoever owns the file.
- **Triangle counts are recorded, never gated.** Budgets and LOD are optimization work that comes
  later; the handoff does not fail, warn or ask on them. A missing model is a **Gap** for
  `pf-model-gen`; a missing clip is a **Gap** for the animation owner the spines name (no PF tool
  authors animation).

## Resume first

List what exists: `ui-kit/sprite-jobs*.json`, `ui-kit/assets/sprites/`, `ui-kit/sprite-manifest.json`,
`ui-kit/component-manifest.json`, `models/model-sources.json`, `models/model-manifest.json`,
`ASSET-MAP.md` (with its `models:` block in a 3D game), `SURFACES.md`, `DIVERGENCES.md`, and
`### Finish bar` in DESIGN.md. Run the checker. Its failures are the to-do list, so do only the phases that are
missing or failing.

```sh
python3 Tools/pf/ux-handoff.py check --ws <ws>   # 0 ok · 1 drift · 2 error (uv run … installs Pillow/PyYAML)
```

## Phases

1. **Surface ledger.** Write SURFACES.md + DIVERGENCES.md per
   `.claude/skills/bmad-ux/references/finish-handoff.md` (the ClassicSpins BMAD fork; when the SKU's
   bmad-ux lacks it, the recipe's Part C §3 lists the fields), adjusted as described in
   the recipe's Part C §3: keep existing filenames, record the mock-versus-capture size
   rule, and name duplicates and theme states. Every IA surface gets a capture or `capture: none` +
   reason. Elements come only from components the spines define.
2. **Sprite jobs.** Build the inventory in `ui-kit/sprite-jobs.json` from DESIGN.md §Components,
   EXPERIENCE.md §Component Patterns and every approved mockup (recipe Part A §1).
   **Checkpoint:** show the user the list with counts and the estimated generation cost, and wait for
   a go.
3. **Extract.** Run `ux-handoff.py requests`, then `asset-gen.py run` in batches, then review contact
   sheets, then `select` (recipe Part A §2–3). Choose by looking. Allow ~6 generations
   per asset, and escalate after two missed rounds. Fix missing transparency with `--keyed` and
   `ux-handoff.py key-out`.
4. **Inventory.** Run `ux-handoff.py manifest`. Author `ui-kit/component-manifest.json` with one
   entry per component the spines define: `id`, `name`, `states` (from EXPERIENCE), `tokens` (DESIGN
   token refs), `sprites` (ids) and a `unity` hint. A component with no sprite says why, for example
   "live text only" or "token-drawn chrome".
5. **3D inventory** (3D only). Declare in `models/model-sources.json` every mesh the package holds
   that `pf-model-gen` did not make, and every rig and clip: `rig`, and per clip `id`, the file or
   take it lives in, `loop` and the `seconds` the spines give it (recipe Part D §1). `pf-model-gen`
   outputs are found without a declaration; declare one only to add its rig, clips or an animated
   replacement mesh. Then run `ux-handoff.py models --probe` (one headless Blender run reads every
   FBX's takes, size and bones; glTF is read without Blender). A model the spines list with no file
   is a Gap.
6. **Asset map.** Write ASSET-MAP.md: per sprite the target size on the reference canvas, draw mode,
   borders, pivot, host layer (rule 16), destination and the size's source; per component its
   sprites. Shape and sizing rules are in the recipe's Part B. This phase is the one that keeps
   a 1335 px master from being imported as a 1335-unit card. In a 3D game add the `models:` block
   (recipe Part D §2): **one** `model_import_scale` for the package, and per model its destination,
   host, rig, `animation` (none, clips, code or both), every clip with the state or event that plays
   it, and the parts a View moves in code. The one scale is what keeps metres from being multiplied
   into the rig twice.
7. **Wire the spines.** Add the reference paragraph to DESIGN.md and EXPERIENCE.md, make the
   handoff's asset table list real sprite ids (and model and clip ids) with a Gap column, draft the
   finish bar from the user's logged rejections, and log each change with `memlog.py` (recipe
   Part C).
8. **Verify and report.** Run `ux-handoff.py check` until it exits 0. Warnings (assumed sizes,
   undecided hosts, upscales, an undecided model scale, files without facts) go in the report, not
   in silence. Also report sprites and models still `pending-user-review`, the finish bar awaiting
   confirmation, and Gaps. End with one line per skipped check: no Unity import, EditMode or play
   session, because this skill changes planning artifacts only.

Phases 1 and 6 can run as parallel subagents once the sprites exist, and phase 5 beside them. Give
each one the relevant recipe part and forbid it to touch any other file.

## Handing on

The next step is `bmad-create-epics-and-stories`. Tell the user two things it must carry:

- A first `function` story that imports and resizes sprites exactly per ASSET-MAP.md and verifies
  PPU 1 and 9-slice borders. In a 3D game it also imports every mapped model and clip at the one
  `model_import_scale`, sets each clip's loop flag, remaps `M_<key>` materials by name, and verifies
  a model's size in world units and each clip's length after import.
- `finish` stories whose Visual Contract cites the SURFACES.md capture and the finish bar.
